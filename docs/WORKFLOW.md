# 다른 컴퓨터에서 작업 이어가기

원격 저장소: https://github.com/tobeperfect0927-creator/minegallery

```sh
git clone https://github.com/tobeperfect0927-creator/minegallery.git
cd minegallery
```

작업 전에 `git pull --ff-only`, 작업 후 변경을 확인하여 커밋하고 `git push`합니다. 로컬 변경이 있으면 먼저 보존합니다.

## 처음 사용하는 컴퓨터

1. Git을 설치하고 저장소에 접근 가능한 계정으로 인증합니다.
2. 확정된 원격 저장소를 복제합니다.
3. `README.md`와 `docs/STATUS.md`를 읽습니다.
4. 브라우저로 시제품을 열어 현재 상태를 확인합니다.

## 매번 작업할 때

1. 저장소의 최신 변경을 내려받습니다. 로컬 변경이 있으면 먼저 확인하고 보존합니다.
2. 이번 작업의 목적을 하나로 정하고 기능별 브랜치에서 작업합니다.
3. 관련 기능을 확인합니다. 실패나 확인하지 못한 부분을 기록합니다.
4. `docs/STATUS.md`에 변경 내용·확인 결과·다음 작업을 추가합니다.
5. 관련 원본과 문서를 함께 커밋하고 원격에 올립니다.
6. 다른 컴퓨터로 이동하기 전에 업로드가 완료됐는지 확인합니다.

같은 파일을 여러 컴퓨터에서 동시에 수정하지 않는 것이 좋습니다. 충돌이 생기면 양쪽 변경을 읽고 해결합니다. 다른 작업의 변경을 강제로 덮어쓰지 않습니다.

## 읽기 쉬운 커밋 제목 예시

- `feat: 체험 날짜별 잔여 정원 표시`
- `fix: 예약 취소 시 환불액 계산 수정`
- `docs: PG 지급 정책과 미완료 항목 기록`
- `release: 오프라인 소비자 웹 배포본 갱신`

## 작업 종료 기록 양식

```text
날짜:
작업 목적:
변경한 내용:
변경한 파일:
확인한 동작과 결과:
확인하지 못한 부분:
남은 작업:
관련 커밋:
```

## 보관할 자료

원본, 결정된 기획, 작업 상태, 필요한 사진의 출처, 배포 재생성 도구를 함께 보관합니다. 생성된 파일과 중간 파일은 구분합니다. Git 범위에 포함할 배포본은 사용자 요청에 맞춰 보관합니다.

비밀번호, API 키, PG 인증정보, 실제 예약자의 개인정보는 커밋하지 않습니다. `.env` 등 로컬 설정은 제외하고 필요한 설정 이름만 예제 문서에 기록합니다.

## 자동 동기화의 범위

Git은 폴더 변경을 자동으로 업로드하지 않습니다. 작업 후 커밋과 업로드가 필요합니다. 이 문서는 이 프로젝트의 작업 규칙이며, 다른 컴퓨터의 모든 채팅이나 다른 프로젝트에 자동 적용되지는 않습니다.
